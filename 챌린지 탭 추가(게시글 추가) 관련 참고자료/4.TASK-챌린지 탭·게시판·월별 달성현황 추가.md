# 챌린지 탭·게시판·월별 달성현황 추가 작업

## 1. 작업 목적

구미도시공사 AI 북큐레이터에 `챌린지` 탭을 추가하고, 로그인 계정과 연결되는 게시판·게시글·첨부파일·댓글 기능을 구현한다.

관리자는 챌린지 게시판의 기간과 목표를 설정하고 게시글을 관리할 수 있어야 한다. 또한 참여자별 전체 달성률과 월별 달성량을 한 화면에서 확인할 수 있어야 한다.

기존 도서 추천, 신간 도서, 추천도서 랭킹, 나의 서재, 계정, 관리자 인증 및 운영 랭킹 데이터는 그대로 보존한다.

## 3. 작업 순서

1. 챌린지 데이터 구조와 API를 구현한다.
2. 사용자용 챌린지 탭, 게시판 목록, 상세 화면, 글쓰기 및 댓글 화면을 구현한다.
3. 관리자 메뉴에 챌린지 관리와 참여 현황 통계를 구현한다.
4. 하단 외부 사이트 배너를 추가한다.
5. 기존 기능 회귀 테스트와 챌린지 기능 테스트를 마친다.
6. 위 기능이 완성된 화면을 기준으로 `99-1` TASK의 전체 색감·UI 개편을 진행한다.
7. 사용자의 화면 확인과 승인 전에는 운영 배포하지 않는다.

`99-1` 문서의 “기존 문구와 기능 유지” 기준 시점은 이번 챌린지 기능 추가가 완료된 이후로 본다. 즉, UI 개편 과정에서 이번에 추가한 챌린지 문구와 기능도 삭제하거나 축소하지 않는다.

## 4. 가장 중요한 보존 원칙

1. 작업 시작 전에 `git status --short`로 기존 변경을 기록한다.
2. 현재 작업 트리는 이미 수정 사항이 있는 상태이므로 다른 작업을 되돌리지 않는다.
3. `git reset --hard`, `git checkout --`, 무관한 파일 전체 덮어쓰기를 사용하지 않는다.
4. `wrangler.jsonc`의 기존 Worker 이름, 계정 ID, `RANKINGS` 바인딩, `RankingStore` 클래스 및 `global-book-ranking` 객체 키를 변경하지 않는다.
5. 기존 계정·즐겨찾기·추천 랭킹·관리자 설정 데이터를 삭제하거나 초기화하지 않는다.
6. 데이터 스키마 변경은 기존 데이터에 영향을 주지 않는 추가 방식으로 적용한다.
7. 디자인 변경 때문에 API나 저장 구조를 임시 로컬 데이터로 대체하지 않는다.
8. 운영 배포는 반드시 기존 안전 배포 절차인 `npm run deploy`를 사용하되, 사용자 승인 전에는 실행하지 않는다.

## 5. 상단 메뉴와 챌린지 진입 화면

현재 메뉴에 `챌린지`를 추가한다.

권장 순서:

`도서 추천 | 신간 도서 | 추천도서 랭킹 | 나의 서재 | 챌린지`

- 관리자 계정에만 보이는 `관리자 메뉴` 동작은 그대로 유지한다.
- `챌린지`를 누르면 등록된 챌린지 게시판 목록과 현재 선택된 게시판의 게시글 목록을 표시한다.
- 챌린지 게시판이 여러 개라면 상단 탭 또는 카드로 구분한다.
- 예시 게시판명은 `필사 챌린지(2027)`, `독서 챌린지(2027)`이며, 실제 명칭과 연도는 관리자가 생성·수정할 수 있어야 한다.
- 진행 중, 예정, 종료 상태와 운영 기간을 화면에서 구분한다.
- 종료된 게시판은 기존 글을 열람할 수 있지만 새 글과 새 댓글은 등록할 수 없다.
- 게시판이 없을 때, 검색 결과가 없을 때, 불러오는 중, 오류가 발생했을 때의 화면을 각각 제공한다.

## 6. 게시글 목록

선택한 챌린지 게시판의 글을 표 형태로 표시한다.

필수 열:

- 번호
- 제목
- 작성자
- 첨부 여부
- 등록일자

동작 기준:

- 최신 글이 위로 오도록 정렬한다.
- 한 페이지에 게시글을 10개씩 표시한다.
- 이전·다음 및 페이지 번호 이동을 제공한다.
- 제목과 작성자 계정 ID를 대상으로 검색할 수 있게 한다.
- 검색 결과에도 동일하게 페이지당 10개 기준을 적용한다.
- 제목을 누르면 게시글 상세 화면으로 이동한다.
- 첨부파일이 있으면 목록의 첨부 열에서 아이콘과 개수를 확인할 수 있게 한다.
- `글쓰기` 버튼은 로그인 사용자에게 제공한다. 비로그인 상태에서 누르면 기존 로그인 창으로 자연스럽게 연결한다.
- 모바일에서는 표가 화면 밖으로 깨지지 않도록 핵심 정보 중심의 카드형 표시 또는 안전한 가로 스크롤을 적용한다.

## 7. 게시글 작성

게시글 작성자는 반드시 현재 로그인 계정으로 서버에서 확인한다. 브라우저가 임의로 전달한 작성자 ID를 신뢰하지 않는다.

필수 입력 및 표시 항목:

- 게시판 선택
- 제목
- 작성자: 현재 로그인 계정 ID를 자동 표시하며 직접 변경할 수 없음
- 본문
- 달성량
- 첨부파일

세부 기준:

- 게시판을 선택하면 관리자가 설정한 목표량과 단위를 자동으로 표시한다.
- 입력 화면에는 `이번 달성량 / 전체 목표량`을 명확히 표시한다.
- 달성량은 0 이상의 숫자만 허용한다.
- 달성량은 해당 게시글 한 건이 월별 실적에 추가하는 값으로 취급한다.
- 게시글의 등록일이 속한 달에 달성량을 합산한다.
- 관리자가 달성량 오기입을 수정하면 전체 달성값, 달성률 및 해당 월 집계를 즉시 다시 계산한다.
- 본문은 긴 내용도 작성할 수 있게 하며, 기본 표시 글자 크기는 읽기 쉬운 16px 이상으로 한다.
- 첨부파일은 게시글당 최대 10개까지 허용한다.
- 첨부 선택 시 파일명, 크기, 삭제 버튼 및 현재 선택 개수를 등록 전에 보여준다.
- 중복 제출을 막고 저장 중 상태와 성공·실패 결과를 명확히 표시한다.
- 챌린지 시작 전 또는 종료 후에는 서버에서도 새 게시글 등록을 거부한다.

첨부파일의 별도 지시가 없다면 다음을 안전 기본값으로 사용한다.

- 허용 형식: JPG, PNG, WebP, GIF, PDF
- 파일당 최대 10MB
- 게시글당 총합 최대 50MB
- 파일 확장자만 믿지 않고 MIME 형식과 실제 파일 특성을 함께 검사
- 실행 가능한 파일, HTML, SVG 등 스크립트 실행 위험이 있는 형식은 거부

## 8. 게시글 상세 화면

- 제목, 작성자, 등록일, 게시판명, 달성량, 전체 목표량, 본문 및 첨부파일을 표시한다.
- 이미지 첨부는 안전한 미리보기를 제공하고, 그 밖의 허용 파일은 다운로드 링크를 제공한다.
- `목록` 버튼으로 기존 검색어와 페이지 상태를 유지한 채 목록으로 돌아갈 수 있게 한다.
- 일반 사용자는 등록 완료 후 게시글의 핵심 실적 값을 임의로 고치거나 삭제할 수 없게 한다.
- 수정이나 삭제가 필요하면 안내 버튼을 통해 다음 문구의 팝업을 표시한다.

  `게시글 수정 또는 삭제가 필요한 경우 관리자 이메일 ps8852@gmuc.or.kr로 요청해 주세요.`

- 관리자는 기존 관리자 로그인과 이메일 인증이 완료된 세션에서만 게시글을 삭제하거나 달성량 오기입을 수정할 수 있다.
- 삭제 전에는 게시글, 첨부파일, 댓글 및 집계에 미치는 영향을 보여주고 한 번 더 확인한다.

## 9. 댓글과 이모지

- 댓글은 외부 `DISQUS` 코드를 연동하지 않는다.
- 기존 홈페이지 로그인 계정과 연결되는 자체 댓글 기능으로 구현한다.
- 댓글 작성자는 서버 세션의 계정 ID로 고정한다.
- 댓글 본문에는 일반 텍스트와 표준 이모지를 입력할 수 있게 한다.
- 댓글 목록에는 작성자 ID와 작성일시를 표시한다.
- 빈 댓글, 과도하게 긴 댓글, HTML 및 스크립트 삽입을 차단한다.
- 게시판 운영 기간이 끝난 뒤에는 기존 댓글을 읽을 수 있지만 새 댓글은 작성할 수 없다.
- 관리자 이메일 인증이 완료된 관리자만 부적절한 댓글을 삭제할 수 있게 한다.
- 일반 사용자의 댓글 수정·삭제 정책은 게시글과 동일하게 관리자 이메일 요청 방식으로 처리한다.

## 10. 관리자 메뉴 개편

기존 관리자 메뉴를 다음 하위 메뉴로 구분한다.

`일반 정보 | 추천도서 관리 | 챌린지 관리`

기존 관리자 정보, 사용자·추천도서 관리, 비밀번호 초기화 등의 기능은 삭제하지 않는다.

### 10-1. 챌린지 게시판 설정

관리자는 이메일 인증이 완료된 세션에서 다음 작업을 할 수 있다.

- 챌린지 게시판 만들기
- 게시판명과 설명 설정
- 챌린지 유형 설정: 예시 `필사`, `독서`
- 시작일과 종료일 설정
- 목표량 설정
- 목표 단위 설정: 예시 `권`, `쪽`, `회`, `개`
- 게시판 정보 수정
- 게시판 종료 또는 보관
- 게시판 삭제

기간이 종료된 게시판은 서버에서 쓰기를 차단하고 열람 전용으로 전환한다.

게시글이나 댓글이 존재하는 게시판은 실수로 즉시 삭제되지 않도록 기본적으로 `보관`을 권장하고, 실제 삭제에는 영향 범위 안내와 명시적 재확인을 적용한다. 삭제 시 관련 게시글, 댓글, 첨부파일 및 통계 데이터를 빠짐없이 정리한다.

### 10-2. 게시글 관리

- 게시판별 게시글을 검색하고 열람할 수 있게 한다.
- 관리자는 달성량 오기입을 수정할 수 있다.
- 관리자는 게시글과 댓글을 삭제할 수 있다.
- 위 관리 기능은 단순히 관리자 화면이 보이는지만 확인하지 말고, API에서도 유효한 관리자 세션과 이메일 인증 상태를 다시 검증한다.
- 누가 언제 어떤 게시글의 달성량을 변경하거나 삭제했는지 최소 감사 기록을 남긴다.

### 10-3. 참여자별 달성 및 월별 집계

선택한 챌린지 게시판의 참여 현황을 참고 이미지와 같은 표로 표시한다.

고정 열:

- 닉네임: 현재 계정 시스템의 사용자 ID를 닉네임처럼 표시
- 목표
- 달성
- 달성률

월별 열:

- 챌린지 시작일부터 종료일까지 포함되는 월을 순서대로 표시한다.
- 참고 이미지의 예시는 `3월, 4월, 5월, 6월, 7월, 8월, 9월, 10월, 11월`이다.
- 기간이 연도를 넘으면 `2027년 12월`, `2028년 1월`처럼 연도를 함께 표시해 혼동을 방지한다.
- 각 월의 값은 해당 사용자가 그 달에 등록한 게시글들의 달성량 합계다.
- 댓글은 달성량 집계에 포함하지 않는다.

계산 규칙:

- `달성 = 모든 월의 달성량 합계`
- `달성률 = 반올림((달성 / 목표) × 100)`
- 목표를 초과해도 100%로 제한하지 않는다.
- 예: 목표 8, 달성 9는 `113%`, 목표 8, 달성 12는 `150%`로 표시한다.
- 목표가 0이거나 잘못된 경우 나눗셈 오류가 나지 않도록 `-`로 표시하고 관리자에게 설정 오류를 알린다.
- 관리자가 달성량을 수정하거나 게시글을 삭제하면 합계와 비율을 서버 기준으로 다시 계산한다.

표시 기준:

- 달성률이 100% 이상인 셀은 참고 이미지처럼 시각적으로 강조하되 색상만으로 의미를 전달하지 않는다.
- 기본 정렬은 달성률 내림차순, 달성량 내림차순, 사용자 ID 오름차순으로 한다.
- 행이 많을 때 사용자 ID 검색 기능을 제공한다.
- 월이 많으면 표 영역만 가로 스크롤되게 하고 닉네임·목표·달성·달성률 열은 가능한 범위에서 고정한다.
- 모바일에서는 고정 열과 월별 내역을 분리한 카드 또는 확장 행으로도 확인할 수 있게 한다.
- 빈 달은 `0` 또는 빈칸 중 하나로 통일하고, 합계 계산에서는 0으로 처리한다.
- 표 데이터는 필요하면 CSV로 내려받을 수 있게 하되, 계정 ID 외 개인정보나 인증 정보를 포함하지 않는다.

모든 주요 화면 하단에 구미도시공사 외부 채널로 이동하는 배너 또는 링크 묶음을 추가한다.

- 홈페이지: <https://www.gmuc.or.kr/index.do>
- 유튜브: <https://www.youtube.com/@gmuc_official>
- 인스타그램: <https://www.instagram.com/gmuc_official/>

동작 기준:

- 각 링크의 서비스명을 텍스트로 명확히 표시한다.
- 새 창에서 열고 `rel="noopener noreferrer"`를 적용한다.
- 키보드로 접근할 수 있어야 하며 적절한 접근성 이름을 제공한다.
- PC와 모바일 모두에서 현재 푸터 문구와 겹치거나 화면 폭을 넘지 않게 한다.
- 외부 사이트 이미지나 로고를 무단으로 원격 삽입하지 않는다. 아이콘을 사용하면 프로젝트에 포함한 안전한 자산 또는 단순 도형을 사용한다.

## 12. 데이터 및 저장 구조

현재 운영 환경은 Cloudflare Worker와 `RankingStore` Durable Object SQLite를 사용한다. 챌린지 구조화 데이터는 기존 테이블을 건드리지 않는 새 테이블로 추가한다.

최소 데이터 개념:

- `challenge_boards`: 이름, 유형, 설명, 시작일, 종료일, 목표량, 목표 단위, 상태
- `challenge_posts`: 게시판, 작성자 계정 ID, 제목, 본문, 달성량, 생성일, 수정일
- `challenge_comments`: 게시글, 작성자 계정 ID, 내용, 생성일
- `challenge_attachments`: 게시글, 저장 키, 원본 파일명, MIME, 크기, 생성일
- `challenge_audit_logs`: 관리자, 대상, 작업 종류, 변경 전후 값, 작업일

구현 원칙:

- 모든 테이블은 안정적인 ID, 필요한 인덱스 및 외래 관계를 갖게 한다.
- 스키마 생성은 `CREATE TABLE IF NOT EXISTS` 등 반복 실행에 안전한 방식으로 한다.
- 달성률과 월별 통계의 원본은 게시글의 달성량이며, 합계와 비율은 서버에서 계산한다.
- 브라우저가 전달한 합계, 달성률 또는 작성자 값은 신뢰하지 않는다.
- 첨부 바이너리를 SQLite JSON이나 Base64로 저장하지 않는다.
- 첨부파일은 별도 Cloudflare R2 버킷을 추가해 저장하고, DB에는 저장 키와 메타데이터만 둔다.
- R2 추가 시에도 기존 `RANKINGS` Durable Object 바인딩과 마이그레이션 식별자를 변경하지 않는다.
- 게시글 삭제, 게시판 삭제 및 회원탈퇴 시 관련 첨부파일이 고아 파일로 남지 않게 정리한다.
- 통계 쿼리는 사용자 수와 게시글이 늘어나도 전체 데이터를 브라우저로 무제한 전송하지 않도록 페이지 처리와 집계를 적용한다.

## 13. API 및 권한 원칙

세부 경로명은 기존 코드 규칙에 맞추되 다음 기능을 각각 제공해야 한다.

- 챌린지 게시판 목록·상세 조회
- 게시판별 게시글 목록·검색·페이지 조회
- 게시글 상세 조회와 등록
- 첨부파일 업로드·조회·다운로드
- 댓글 목록과 등록
- 관리자 게시판 생성·수정·보관·삭제
- 관리자 게시글 달성량 수정·삭제
- 관리자 댓글 삭제
- 관리자 참여자별 전체·월별 집계 조회

권한 기준:

- 게시판과 게시글 열람은 비로그인 사용자도 가능하다.
- 게시글 및 댓글 등록은 로그인 계정만 가능하다.
- 작성자는 요청 본문이 아니라 서버 세션에서 결정한다.
- 관리자 변경 작업은 유효한 관리자 세션과 완료된 이메일 인증을 모두 요구한다.
- 변경 API에는 기존 `sameOrigin` 검사와 동일하거나 더 강한 CSRF 방어를 적용한다.
- 출력 시 HTML 이스케이프 또는 허용 목록 기반 정화를 적용해 XSS를 방지한다.
- 게시글, 댓글 및 첨부 업로드에 크기 제한과 과도한 요청 방지 대책을 적용한다.
- 존재하지 않는 대상, 종료된 게시판, 권한 부족 및 입력 오류를 구분되는 상태 코드와 사용자용 메시지로 반환한다.

## 14. 개인정보처리방침과 계정 처리

- 챌린지 게시글, 댓글, 첨부파일, 작성자 계정 ID 및 활동 내역이 새로 저장된다는 사실을 개인정보처리방침에 반영한다.
- 이름, 이메일 등 불필요한 개인정보를 챌린지 글쓰기에서 추가로 받지 않는다.
- 화면의 `닉네임`은 별도 개인정보 필드가 아니라 현재 계정 ID를 표시하는 의미로 사용한다.
- 회원탈퇴 시 해당 계정과 연결된 챌린지 데이터의 삭제 또는 익명화 정책을 명확히 정하고 실제 처리와 문서가 일치하게 한다.
- 관리자 통계와 CSV에는 비밀번호 해시, 세션 정보, 기기 식별값, 관리자 인증값을 절대 포함하지 않는다.

## 15. UI·접근성 기준

- 기존 페이지의 내비게이션 방식과 시각적 일관성을 유지하면서 챌린지 화면을 추가한다.
- 버튼, 입력란, 표, 팝업 및 댓글 영역에 명확한 레이블을 제공한다.
- 키보드만으로 목록, 글쓰기, 댓글, 팝업 및 관리자 표를 사용할 수 있게 한다.
- 팝업이 열리면 초점이 내부로 이동하고 닫을 때 원래 버튼으로 돌아오게 한다.
- 성공·실패·검증 오류를 색상만이 아니라 문구로 함께 안내한다.
- 긴 제목, 긴 계정 ID, 긴 파일명, 긴 본문 및 큰 달성률 값에서도 레이아웃이 깨지지 않게 한다.
- 360px 모바일, 태블릿, 일반 PC 및 넓은 PC 화면에서 확인한다.
- 이후 `99-1` TASK의 화이트·페리윙클 블루 테마를 챌린지와 관리자 통계 화면에도 동일하게 적용한다.

## 16. 테스트 및 검수

### 16-1. 기존 기능 회귀 테스트

- 도서 추천 조건 선택과 추천 결과
- 신간 도서 표시
- 추천도서 랭킹
- 로그인, 로그아웃, ID 생성 및 비밀번호 초기화
- 나의 서재 저장과 복원
- 관리자 로그인과 이메일 인증
- 사용자·추천도서 관리
- `npm run check`
- 기존 `npm test`
- 운영 랭킹 데이터가 작업 전후 동일하게 보존되는지 확인

### 16-2. 챌린지 기능 테스트

- 예정·진행·종료 게시판의 쓰기 허용 여부
- 게시판 목록, 게시글 검색 및 페이지당 10개 표시
- 비로그인 게시글·댓글 작성 차단
- 로그인 계정 ID가 작성자로 고정되는지 확인
- 첨부 0개, 1개, 10개 성공 및 11개 차단
- 허용되지 않은 파일과 용량 초과 파일 차단
- 댓글의 일반 텍스트와 이모지 표시
- HTML 및 스크립트 문자열이 실행되지 않는지 확인
- 일반 사용자가 관리자 수정·삭제 API를 호출할 수 없는지 확인
- 관리자 이메일 미인증 상태에서 관리 작업이 차단되는지 확인
- 관리자 달성량 수정과 게시글 삭제 후 통계 재계산
- 게시글 삭제 시 댓글과 R2 첨부파일 정리

### 16-3. 월별 통계 계산 테스트

- 목표 8, 달성 9일 때 113%
- 목표 8, 달성 12일 때 150%
- 여러 게시글이 같은 달에 있으면 합산
- 서로 다른 달의 값이 해당 월 열에 각각 표시
- 달성량 수정 시 해당 월, 전체 달성, 달성률이 함께 변경
- 게시글 삭제 시 해당 월, 전체 달성, 달성률이 함께 감소
- 목표 초과 달성률을 100%로 제한하지 않음
- 빈 달은 0으로 계산
- 목표 0에서 오류 없이 `-` 표시
- 연도를 넘는 챌린지에서 월 열의 연도 구분
- 다수 참여자와 다수 월에서도 정렬·검색·가로 스크롤 정상 동작

## 17. 완료 조건

다음 조건을 모두 충족해야 작업 완료로 본다.

1. 사용자 메뉴에 챌린지 탭이 있고 게시판 목록·검색·페이지 이동·상세·글쓰기가 동작한다.
2. 게시글은 로그인 계정과 연결되고 달성량 및 최대 10개 첨부파일을 저장할 수 있다.
3. DISQUS 없이 로그인 계정 기반 댓글과 이모지가 동작한다.
4. 관리자가 게시판의 기간, 목표량과 단위를 설정할 수 있다.
5. 종료된 게시판은 열람 가능하지만 게시글과 댓글을 새로 등록할 수 없다.
6. 관리자가 이메일 인증 후 게시글 삭제와 달성량 수정을 할 수 있다.
7. 관리자 화면에 닉네임, 목표, 달성, 달성률 및 기간 내 월별 집계가 표시된다.
8. 달성률은 반올림하며 100%를 넘는 값을 그대로 표시한다.
9. 하단에 구미도시공사 홈페이지, 유튜브, 인스타그램 링크가 정확히 연결된다.
10. 기존 계정, 서재, 추천 및 랭킹 기능과 데이터가 훼손되지 않는다.
11. PC·태블릿·모바일에서 주요 화면이 정상 동작한다.
12. 자동 검사와 수동 검수 결과를 사용자에게 보고하고, 사용자 승인 전에는 운영 배포하지 않는다.
