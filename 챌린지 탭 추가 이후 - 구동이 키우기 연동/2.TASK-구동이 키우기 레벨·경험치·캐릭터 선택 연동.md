# 구동이 키우기 레벨·경험치·캐릭터 선택 연동 TASK

> 최종 보강: 2026-09-04 — `나의 정보`를 개인정보 변경·나의 구동이 탭으로 개편하고 기존 챌린지 글쓰기의 `이번 달성량` 입력값과 구동이 EXP를 필수 단일 원천으로 직접 연동

## 1. 작업 목적

구미도시공사 AI 북큐레이터의 로그인 계정에 캐릭터 `구동이`를 연결한다.

사용자는 도서 추천과 챌린지 달성량을 통해 경험치를 얻고, 경험치에 따라 구동이의 레벨과 기본 모습이 성장하는 과정을 확인할 수 있어야 한다. 레벨별로 해금된 모습은 별도의 선택창에서 골라 사용할 수 있어야 한다.

기존 도서 추천, 일일 추천 기록, 계정, 즐겨찾기, 랭킹, 챌린지 게시판, 월별 집계, 관리자 인증 및 운영 데이터를 그대로 보존한다.

이미지가 모두 준비되기 전에는 임의의 최종 캐릭터 이미지를 제작하거나 운영 배포하지 않는다. 기능 개발 중에는 이미지가 없을 때도 깨지지 않는 공통 실루엣 또는 텍스트 자리표시자를 사용한다.

## 3. 확정 경험치 및 레벨 규칙

각 단계의 필요 경험치는 해당 레벨에 진입한 뒤 다음 레벨로 올라가는 데 추가로 필요한 경험치로 해석한다.

| 현재 레벨 | 다음 레벨까지 필요한 경험치 | 누적 경험치 범위 | 표시 |
|---|---:|---:|---|
| LV 1 | 5 EXP | 0~4 | LV 1 |
| LV 2 | 10 EXP | 5~14 | LV 2 |
| LV 3 | 30 EXP | 15~44 | LV 3 |
| LV 4 | 50 EXP | 45~94 | LV 4 |
| LV 5 | 없음 | 95 이상 | LV MAX |

누적 레벨 경계값은 다음과 같다.

- LV 1 시작: 누적 0 EXP
- LV 2 시작: 누적 5 EXP
- LV 3 시작: 누적 15 EXP
- LV 4 시작: 누적 45 EXP
- LV 5 시작: 누적 95 EXP

경험치는 서버에 누적으로 보존한다. 브라우저가 전달한 현재 경험치, 레벨 또는 해금 상태는 신뢰하지 않고 서버가 경험치 원장을 기준으로 계산한다.

## 4. 나의 정보 화면과 경험치 UI

로그인 후 상단의 `나의 정보`를 클릭하면 기존의 간단한 팝업 대신 충분한 내용을 확인하고 수정할 수 있는 전용 `나의 정보` 화면을 연다. 이 화면은 다음 두 개의 탭으로 구성한다.

1. `개인정보 변경`
2. `나의 구동이`

처음 진입할 때 기본 활성 탭은 `개인정보 변경`으로 한다. 탭을 전환해도 같은 나의 정보 화면 안에서 내용만 바뀌며, 데스크톱·태블릿·모바일에서 탭 이름과 선택 상태가 명확히 보여야 한다. 키보드 방향키와 Tab 키로 탭을 이동할 수 있고 현재 탭에는 `aria-selected` 등 접근성 상태를 제공한다.

### 4-1. 개인정보 변경 탭

기존 나의 정보에서 제공하던 개인정보 조회·변경 항목을 이 탭으로 옮긴다. 비밀번호 변경 영역에는 다음 입력란을 순서대로 제공한다.

- 기존 비밀번호
- 새 비밀번호
- 새 비밀번호 확인

비밀번호 변경 동작은 다음 기준을 따른다.

- 세 입력란은 모두 비밀번호 형식으로 표시하고 제출 시 필수값으로 검증한다.
- 서버에서 기존 비밀번호가 현재 계정의 비밀번호와 일치하는지 확인한다.
- 새 비밀번호와 새 비밀번호 확인이 일치해야 한다.
- 새 비밀번호는 기존 서비스의 비밀번호 복잡도·길이 정책을 동일하게 적용한다.
- 기존 비밀번호와 동일한 새 비밀번호는 허용하지 않는다.
- 오류가 있으면 해당 입력란 가까이에 원인을 표시하고, 성공하면 세 입력값을 즉시 비운 뒤 변경 완료를 안내한다.
- 비밀번호 원문은 로그, 응답 또는 브라우저 저장소에 남기지 않는다.
- 비밀번호 변경 API에는 로그인 세션, 기존 `sameOrigin` 검사와 기존 CSRF 방어 정책을 적용한다.

기존 `회원탈퇴` 기능과 안내는 이 탭의 하단에 배치한다. 일반 개인정보 저장이나 비밀번호 변경 버튼과 혼동되지 않도록 별도의 위험 영역으로 구분하고, 기존 재확인 절차와 관련 데이터 삭제 동작은 그대로 유지한다.

### 4-2. 나의 구동이 탭

로그인 계정의 구동이 현황과 현재 모습을 한 화면에서 확인할 수 있게 한다. 다음 정보를 표시한다.

- 현재 선택한 구동이 모습
- 캐릭터 이름 `구동이`
- 현재 레벨 또는 `LV MAX`와 누적 총 EXP
- 5칸 경험치 바
- 현재 레벨 진행 경험치와 다음 레벨 필요 경험치
- 다음 레벨까지 남은 EXP. 단, LV MAX에서는 최대 레벨 안내
- 현재 보유 중인 모습의 수
- `모습 바꾸기` 버튼

표시 예시:

```text
구동이  LV 1
■□□□□  EXP (1/5)
```

경험치 숫자는 누적값이 아니라 현재 레벨 안에서 쌓인 값으로 표시한다.

- 누적 EXP 8인 경우: `LV 2`, `EXP (3/10)`
- 누적 EXP 20인 경우: `LV 3`, `EXP (5/30)`
- 누적 EXP 95 이상인 경우: `LV MAX`, `■■■■■`, `EXP (MAX)`

5칸 바는 현재 레벨 진행률을 비례 표시한다. 경험치가 0보다 크지만 20% 미만이면 최소 1칸을 채우고, 다음 레벨에 도달하기 전에는 최대 4칸까지만 채운다. LV MAX는 5칸을 모두 채운다. 정확한 값은 항상 `EXP (현재/필요)` 문구로 함께 제공해 색상이나 칸 수에만 의존하지 않는다.

권장 배치는 다음과 같다.

1. 상단 계정 영역에는 선택한 구동이의 작은 썸네일, 이름과 레벨을 간결하게 표시한다.
2. `나의 구동이` 탭에는 큰 캐릭터 이미지, 레벨, 총 EXP, 5칸 경험치 바, 현재 레벨 진행 수치, 다음 레벨 안내와 `모습 바꾸기` 버튼을 표시한다.
3. 모바일에서는 상단을 과도하게 넓히지 않고, 상세 경험치와 모습 변경은 `나의 구동이` 탭에서 제공한다.

레벨이 오르면 한 번만 레벨업 안내를 보여준다. 같은 레벨업을 새로고침할 때마다 반복 표시하지 않는다.

## 5. 도서 추천 제한과 추천 경험치

### 5-1. 일일 도서 추천 제한

- 로그인 사용자 ID별 하루 최대 추천 도서 수는 30권이다.
- 날짜 경계는 `Asia/Seoul` 기준 자정이다.
- 추천 결과에서 실제로 사용자에게 새로 제공된 도서 수만 일일 사용량에 더한다.
- 동일 추천 결과 안에서 `다른 추천 보기`로 이미 받은 최대 30권의 후보를 순환하는 것은 추가 추천 권수로 계산하지 않는다.
- 남은 추천 가능 권수가 6권보다 적으면 남은 권수만 제공한다.
- 30권을 모두 사용하면 서버가 추가 추천을 거부하고 다음 초기화 시각과 안내 문구를 반환한다.
- 프런트 화면에는 `오늘 추천 18/30권`처럼 사용량을 표시한다.
- 브라우저 저장값을 삭제하거나 요청 본문을 바꿔도 제한을 우회할 수 없도록 서버에서 검사한다.

### 5-2. 추천 경험치

- 도서가 1권 이상 정상 제공된 추천 요청 1회당 `+1 EXP`를 지급한다.
- 추천으로 받을 수 있는 경험치는 사용자 ID별 하루 최대 `4 EXP`다.
- 한 번 받은 추천 후보 안에서 `다른 추천 보기`를 누르는 동작은 경험치를 추가 지급하지 않는다.
- 같은 요청의 재전송, 네트워크 재시도 또는 중복 제출로 경험치가 두 번 지급되지 않게 한다.
- 추천 도서 30권 제한에 도달했거나 결과가 0권인 요청에는 경험치를 지급하지 않는다.

현재 추천 화면이 한 번의 서버 요청에서 많은 후보를 받아 브라우저에서 순환하는 구조이므로, 구현 시 서버가 하루 남은 한도 안의 후보만 반환하고 성공한 추천 세션 ID 하나를 발급해야 한다. 경험치 원장에는 이 추천 세션 ID를 고유 키로 기록한다.

## 6. 챌린지 경험치

### 6-1. 기존 달성량 입력란과의 필수 직접 연동

현재 챌린지 게시글 작성 화면에는 이미 `이번 달성량` 입력란이 구현되어 있다.

| 처리 단계 | 현재 연결 대상 | 구동이 연동 기준 |
|---|---|---|
| 사용자 입력 | `#challengePostAchievement` | 한 게시글에서 사용자가 입력한 이번 달성량 |
| 요청 전송 | 게시글 등록 FormData의 `achievement` | 별도의 EXP 입력값을 추가하지 않고 이 값을 그대로 전송 |
| 서버 저장 | `challenge_posts.achievement` | 서버 검증을 통과해 실제 저장된 값만 신뢰 |
| 경험치 원장 | `mascot_xp_events`, `source_id=post_id` | `challenge_posts.achievement × 3` |

이 연결은 선택 기능이 아니라 필수 완료 조건이다. 구동이 EXP를 게시글 수, 댓글 수, 게시판 목표량 또는 브라우저가 별도로 계산해 전달한 값으로 지급해서는 안 된다. 반드시 해당 게시글의 서버 저장 필드 `challenge_posts.achievement` 하나만 EXP의 원천값으로 사용한다.

공식 계산식:

```text
게시글 획득 EXP = 서버에 저장된 이번 달성량(achievement) × 3
```

- 게시글 1개를 작성하더라도 `이번 달성량`을 반드시 입력한다.
- 달성량 1인 게시글 1개: `1 × 3 = 3 EXP`
- 달성량 2인 게시글 1개: `2 × 3 = 6 EXP`
- 달성량 10인 게시글 1개: `10 × 3 = 30 EXP`
- 게시글 10개라는 이유만으로 EXP를 지급하지 않는다. 각 게시글에 저장된 달성량의 합계에만 3을 곱한다.
- 게시판의 `전체 목표량`은 진행률 계산과 안내에만 사용하며 EXP 배수 계산에는 사용하지 않는다.

글쓰기 화면에서는 사용자가 값을 입력할 때 `예상 획득 EXP +6`처럼 `이번 달성량 × 3`의 예상값을 즉시 보여준다. 이 값은 안내용이며, 실제 지급값은 등록 완료 후 서버가 저장한 달성량으로 다시 계산한다.

게시글 등록 API의 성공 응답에는 최소한 다음 결과를 포함해 화면이 서버 확정값을 바로 표시할 수 있게 한다.

- 저장된 게시글 ID
- 서버가 확정한 달성량
- 이번 게시글로 반영된 EXP
- 반영 후 총 EXP와 현재 레벨
- 레벨업 여부

### 6-2. 지급과 제한 규칙

- 챌린지 게시글에 저장된 `달성량 × 3`만큼 경험치를 지급한다.
- 게시글 수가 아니라 서버에 저장된 달성량이 기준이다.
- 예: 달성량 2인 게시글은 `2 × 3 = 6 EXP`를 지급한다.
- 챌린지 경험치에는 일일 상한이 없다.
- 댓글, 첨부파일 개수, 게시글 제목이나 본문 길이는 경험치에 영향을 주지 않는다.
- 예정·종료·보관 게시판처럼 게시글 등록이 허용되지 않는 상태에서는 경험치도 지급하지 않는다.

### 6-3. 등록·수정·삭제 생명주기

게시글 저장과 경험치 반영은 같은 Durable Object 처리 흐름에서 원자적으로 완료한다.

- 게시글 저장이 실패하면 EXP를 지급하지 않는다.
- EXP 원장 저장이 실패하면 게시글 등록 전체를 성공으로 응답하지 않는다.
- 네트워크 재시도나 등록 버튼 중복 클릭이 발생해도 `source_id=post_id` 고유 제약으로 한 번만 지급한다.
- 사용자가 입력한 달성량과 경험치 원장의 기준 달성량을 따로 복제해 독립적으로 관리하지 않는다.
- 게시글 상세, 관리자 게시글 관리, 월별 달성 통계와 구동이 EXP가 모두 같은 `challenge_posts.achievement` 값을 사용해야 한다.

관리자가 달성량을 수정하면 해당 게시글의 경험치도 즉시 다시 계산한다.

- 달성량 2에서 3으로 수정: 6 EXP에서 9 EXP로 변경
- 달성량 3에서 1로 수정: 9 EXP에서 3 EXP로 변경
- 게시글 삭제: 해당 게시글에서 발생한 경험치 전부 제거
- 게시판 삭제: 게시판의 모든 게시글 경험치 제거
- 회원탈퇴: 구동이 프로필과 경험치 원장을 함께 삭제

수정 또는 삭제로 누적 경험치가 레벨 기준 아래로 내려가면 레벨도 서버 기준으로 내려간다. 현재 선택 모습이 더 이상 해금 조건을 만족하지 않으면 해당 레벨의 기본 모습으로 자동 변경하고 사용자에게 안내한다.

관리자 수정 시 적용할 차이 계산은 다음과 같다.

```text
EXP 변경량 = (수정 후 달성량 - 수정 전 달성량) × 3
```

월별 집계 결과를 다시 곱해 경험치를 만들지 않는다. 게시글별 고유 원장 항목을 수정한 뒤 전체 EXP를 합산해야 게시글 수정·삭제와 정확히 연결된다.

현재 챌린지 달성량은 소수를 허용하므로 경험치도 `달성량 × 3`의 계산 결과를 그대로 보존하고 화면에는 최대 소수 둘째 자리까지 표시한다. 경험치를 정수로만 운영하려면 구현 전에 챌린지 달성량의 소수 처리 규칙을 별도로 변경해야 한다.

## 7. 레벨별 기본 모습과 해금 모습

해금은 누적 방식으로 적용한다. 높은 레벨에 도달해도 이전 레벨에서 해금한 모습은 계속 선택할 수 있다.

| 해금 레벨 | 레벨 기본 모습 | 추가 해금 모습 | 크기 기준 |
|---|---|---|---|
| LV 1 | 갓난아기, 공갈 꼭지를 문 모습 | 없음 | 현재 기본 캐릭터의 약 2/5 |
| LV 2 | 교복을 입은 고등학생 모습 | 없음 | 현재 기본 캐릭터의 약 4/5 |
| LV 3 | 현재 기본 구동이 모습 | 책을 들고 앉아 있는 모습 | 현재 크기 |
| LV 4 | 캐주얼 복장을 입은 모습 | 방방 뛰며 좋아하는 모습 | 현재 크기 |
| LV 5 | 정장을 입은 모습 | 안전모를 쓴 모습, 하트가 나오는 모습 | 현재 크기 |

레벨이 처음 올라가면 새 레벨의 기본 모습을 자동 선택한다. 이후 사용자가 모습 변경창에서 다른 보유 모습을 선택하면 그 선택을 계정에 저장하고 다시 로그인해도 유지한다.

캐릭터 이름은 `구동이`로 고정하며 이번 TASK에서는 사용자 이름 변경 기능을 만들지 않는다.

## 9. 모습 변경창

`나의 구동이` 탭의 `모습 바꾸기` 버튼을 누르면 현재 계정이 보유 중인 모습만 보여주는 별도 모달을 연다. 보유 중인 모습은 현재 레벨까지 누적 해금된 모습이며, 아직 해금되지 않은 모습은 이 모달에 표시하지 않는다.

각 모습 카드는 다음을 표시한다.

- 캐릭터 미리보기
- 모습 이름
- 해금 레벨
- 선택 중 상태

동작 기준:

- 현재 레벨 이하에서 해금되어 보유 중인 모습만 목록에 표시하고 선택 가능
- 아직 해금되지 않은 모습과 잠김 카드는 목록에 노출하지 않음
- 현재 적용 중인 모습은 `사용 중`으로 명확히 표시하고 중복 저장하지 않음
- 보유 모습이 하나뿐이어도 해당 모습을 표시하며, 선택 변경이 불가능하다는 안내를 제공
- 서버가 현재 레벨과 해금 상태를 다시 확인한 뒤 선택값 저장
- 저장 성공 후 상단 썸네일과 `나의 구동이` 탭의 큰 이미지를 즉시 갱신
- 키보드만으로 모달 열기, 카드 이동, 선택과 닫기 가능
- 모달을 닫으면 열기 버튼으로 초점 복귀
- 모바일에서는 한 열, 태블릿은 두 열, 데스크톱은 세 열 카드 배치

## 10. 서버 데이터 구조

기존 `RankingStore` Durable Object와 `global-book-ranking` 객체 키를 그대로 사용한다. 기존 테이블을 변경하거나 초기화하지 않고 추가 테이블로 구현한다.

권장 테이블:

### `mascot_profiles`

- `user_id` 기본키
- `selected_appearance_id`
- `last_seen_level`
- `created_at`
- `updated_at`

### `mascot_xp_events`

- `event_id` 기본키
- `user_id`
- `source_type`: `recommendation` 또는 `challenge`
- `source_id`: 추천 세션 ID 또는 챌린지 게시글 ID
- `xp_amount`
- `earned_date`: 서울 날짜 기준 `YYYY-MM-DD`
- `created_at`
- `updated_at`
- `(source_type, source_id)` 고유 제약으로 중복 지급 방지

### `recommendation_daily_usage`

- `user_id`
- `usage_date`: 서울 날짜 기준 `YYYY-MM-DD`
- `book_count`
- `xp_count`
- `updated_at`
- `(user_id, usage_date)` 복합 기본키

구현 원칙:

- 경험치 총합은 경험치 원장의 합계가 기준이다.
- 성능을 위해 프로필에 합계 캐시를 두더라도 원장과 불일치하면 서버가 원장에서 복구할 수 있어야 한다.
- 추천 한도 검사, 추천 세션 저장, 일일 사용량 증가와 경험치 지급은 가능한 한 같은 Durable Object 요청 안에서 원자적으로 처리한다.
- 챌린지 게시글 생성, 달성량 수정·삭제와 해당 경험치 반영도 같은 Durable Object 안에서 처리한다.
- 경험치 수정·제거와 모습 강제 변경은 감사 가능한 기록을 남긴다.
- 관리자나 브라우저가 임의로 EXP를 직접 지정하는 일반 API는 만들지 않는다.

## 11. 기존 데이터 반영

최초 배포 시 기존 활동을 버리지 않기 위해 반복 실행에 안전한 1회 보정 절차를 둔다.

- 기존 `challenge_posts`: 각 게시글의 `achievement × 3`을 `source_id=post_id`로 등록
- 기존 `recommendation_sessions`: 서울 날짜별 정상 추천 세션을 시간순으로 확인해 하루 최대 4개까지 세션당 1 EXP 등록
- 과거 추천 도서 수는 경험치 보정에만 사용하고, 기능 배포일의 신규 일일 30권 제한 사용량에는 합산하지 않는다.
- 고유 키를 사용해 보정 스크립트를 다시 실행해도 경험치가 중복되지 않게 한다.
- 보정 전후 사용자 수, 추천 세션 수, 챌린지 게시글 수와 기존 랭킹 데이터가 동일한지 검사한다.

기존 활동을 소급하지 않고 모두 LV 1부터 시작하도록 정책을 바꾸려면 구현 전에 이 절만 변경한다.

## 12. API

세부 경로는 기존 코드 규칙에 맞추되 다음 기능을 제공한다.

- 현재 로그인 사용자의 구동이 프로필, 총 EXP, 레벨, 현재 레벨 진행도와 해금 모습 목록 조회
- 해금된 구동이 모습 선택
- 현재 비밀번호 확인 후 새 비밀번호로 변경
- 오늘 추천 도서 사용량, 남은 권수, 추천 EXP와 남은 EXP 획득 횟수 조회
- 추천 성공 시 일일 도서 수와 경험치를 함께 반영
- 챌린지 게시글 생성·달성량 수정·삭제 시 경험치 자동 반영

모든 변경 API는 서버 로그인 세션과 기존 `sameOrigin` 검사를 요구한다. 사용자 ID, EXP, 레벨, 해금 상태를 요청 본문에서 신뢰하지 않는다.

비로그인 방문자는 기존 도서 탐색 화면을 볼 수 있지만 구동이 경험치를 적립하거나 모습을 저장할 수 없다. 경험치가 발생하는 동작에서는 로그인 안내를 제공한다. 일일 30권 제한을 비로그인 방문자에게도 적용해야 한다면 계정 외 식별 기준이 필요하므로 별도 정책으로 확정한다.

## 13. 오류 및 경계 처리

- 추천 API 실패 또는 추천 결과 0권: 추천 권수와 EXP 모두 증가시키지 않음
- 같은 추천 세션 재전송: 최초 1회만 반영
- 같은 챌린지 게시글 재전송: 게시글과 경험치 모두 중복 생성하지 않음
- 달성량 0: 챌린지 EXP 0
- 음수, 숫자가 아닌 값, 허용 최대치를 넘는 달성량: 기존 챌린지 검증과 동일하게 거부
- 일일 추천 사용량이 30권을 넘도록 동시에 요청: Durable Object에서 직렬 처리해 최대 30권까지만 허용
- 추천 일일 EXP가 이미 4: 추천 도서는 남은 한도 내에서 제공하되 EXP는 추가하지 않음
- 이미지 누락 또는 로딩 실패: 자리표시자와 모습 이름 유지
- 선택 모습이 잠기거나 존재하지 않음: 현재 레벨 기본 모습으로 복구
- LV MAX 이후 EXP: 챌린지 기록과 원장은 계속 보존하되 레벨은 5를 넘기지 않음

## 14. 개인정보 및 회원탈퇴

- 로그인 후 `나의 정보` 화면은 `개인정보 변경`과 `나의 구동이` 두 탭으로 제공한다.
- 기존 회원탈퇴 기능은 `개인정보 변경` 탭 하단의 별도 위험 영역으로 이동한다.
- 비밀번호 변경 시 기존 비밀번호를 서버에서 검증하고, 새 비밀번호와 확인값의 일치 여부 및 기존 비밀번호 정책을 검사한다.
- 비밀번호는 기존 서비스와 동일한 안전한 단방향 해시 방식으로 저장하며 원문을 저장하거나 기록하지 않는다.
- 구동이 프로필에는 사용자 ID, 경험치 원장, 선택 모습만 저장한다.
- 이름, 이메일, 생년월일 등 추가 개인정보를 받지 않는다.
- 경험치 획득 원인은 추천 세션 ID와 챌린지 게시글 ID만 연결한다.
- 회원탈퇴 시 `mascot_profiles`, `mascot_xp_events`, `recommendation_daily_usage`의 해당 사용자 데이터를 함께 삭제한다.
- 개인정보처리방침에 캐릭터 경험치와 선택 모습 저장 목적 및 회원탈퇴 시 삭제 사실을 추가한다.

## 15. 관리자 기능

이번 TASK의 기본 범위에서는 관리자가 사용자의 EXP를 임의로 올리거나 내리는 기능을 만들지 않는다.

관리자 화면에는 장애 확인을 위해 다음 읽기 정보만 제공할 수 있다.

- 사용자 현재 레벨과 총 EXP
- 추천 EXP와 챌린지 EXP의 합계
- 현재 선택 모습
- 마지막 경험치 발생 시각

잘못된 챌린지 달성량은 기존 게시글 관리 기능에서 수정하며, 구동이 경험치는 그 결과에 따라 자동으로 재계산한다.

## 16. 테스트

### 16-1. 레벨 계산

- 누적 0, 4 EXP는 LV 1
- 누적 5, 14 EXP는 LV 2
- 누적 15, 44 EXP는 LV 3
- 누적 45, 94 EXP는 LV 4
- 누적 95 이상은 LV MAX
- 각 레벨에서 `EXP (현재/필요)` 계산 확인
- LV MAX에서 5칸과 `EXP (MAX)` 표시 확인

### 16-2. 추천 제한과 경험치

- 성공 추천 1회당 1 EXP
- 같은 추천 세션 재전송 시 중복 EXP 없음
- 하루 다섯 번째 성공 추천부터 추천 EXP가 증가하지 않음
- 하루 실제 제공 도서가 30권을 넘지 않음
- 29권 사용 후 최대 1권만 추가 제공
- 다른 추천 보기로 동일 후보를 순환할 때 권수와 EXP가 증가하지 않음
- 서울 자정 이후 새 날짜 사용량이 0으로 시작
- 동시에 여러 요청을 보내도 30권과 4 EXP 상한 유지
- API 실패와 0권 결과에 사용량 및 EXP 미반영

### 16-3. 챌린지 경험치

- 글쓰기 화면에 `이번 달성량` 입력란이 존재하고 필수 입력으로 동작
- 입력 중 `예상 획득 EXP = 이번 달성량 × 3` 표시
- 게시글 1개만 작성해도 그 게시글의 달성량을 기준으로 EXP 지급
- 달성량 2 게시글 등록 시 6 EXP
- 게시글 수와 관계없이 `SUM(각 게시글 달성량 × 3)`과 챌린지 EXP 합계가 일치
- 게시판 전체 목표량을 바꿔도 기존 게시글 EXP는 변하지 않음
- 같은 게시글 중복 제출 시 1회만 반영
- 달성량 수정 시 차이만 정확히 반영
- 게시글·게시판 삭제 시 연결 EXP 제거
- 챌린지 경험치에는 일일 상한이 없음
- 달성량 소수 사용 시 `달성량 × 3` 값 보존
- EXP 감소로 레벨 하락 시 잠긴 선택 모습 자동 해제

### 16-4. 모습 변경

- LV 1에서 아기 모습만 선택 가능
- LV 2에서 고등학생 기본 모습으로 전환
- LV 3에서 기본 모습과 책 읽는 모습 해금
- LV 4에서 캐주얼 기본 모습과 뛰는 모습 해금
- LV 5에서 정장 기본 모습, 안전모와 하트 모습 해금
- 이전 레벨 해금 모습 계속 선택 가능
- `나의 구동이` 탭에 현재 모습, 레벨, 총 EXP, 현재 레벨 EXP, 다음 레벨까지 남은 EXP와 보유 모습 수 표시
- `모습 바꾸기` 모달에는 현재 보유 중인 모습만 표시하고 잠긴 모습은 표시하지 않음
- 보유 모습이 하나뿐인 경우에도 현재 모습과 변경 불가 안내 표시
- 잠긴 모습 ID를 직접 API로 요청해도 선택 차단
- 선택 모습이 재로그인과 다른 기기에서도 유지
- 이미지 누락·오류 시 자리표시자 표시

### 16-5. 나의 정보와 비밀번호 변경

- 로그인 후 `나의 정보` 클릭 시 간단한 기존 팝업 대신 두 탭이 있는 나의 정보 화면 표시
- `개인정보 변경`과 `나의 구동이` 탭 전환 및 선택 상태 표시
- 기존 개인정보 조회·변경 기능이 `개인정보 변경` 탭에서 정상 동작
- 기존 비밀번호가 틀리면 변경 거부
- 새 비밀번호와 새 비밀번호 확인이 다르면 변경 거부
- 비밀번호 정책을 충족하지 않거나 기존 비밀번호와 같으면 변경 거부
- 정상 변경 후 새 비밀번호로 로그인 가능하고 기존 비밀번호로 로그인 불가
- 비밀번호 입력값이 로그·응답·브라우저 저장소에 남지 않음
- 기존 회원탈퇴 기능이 `개인정보 변경` 탭 하단에서 기존 확인 절차대로 동작
- 탭 키보드 탐색, 포커스 이동과 모바일 레이아웃 확인

### 16-6. 회귀 및 화면

## 17. 구현 순서

1. 사용자가 레벨별·해금별 이미지 파일을 이 폴더에 추가한다.
2. 이미지 목록과 파일명을 확인하고 원본을 별도로 백업한다.
3. 기존 추천 세션·챌린지·계정 구조와 운영 데이터 백업을 확인한다.
4. 구동이 프로필, 경험치 원장과 일일 추천 사용량 테이블을 추가한다.
5. 레벨 계산과 기존 데이터 보정 로직을 구현하고 단위 테스트한다.
6. 추천 30권 제한과 하루 최대 추천 EXP 4를 서버에서 원자적으로 처리한다.
7. 챌린지 생성·수정·삭제에 경험치 원장을 연결한다.
8. 기존 나의 정보 팝업을 `개인정보 변경`과 `나의 구동이` 두 탭이 있는 나의 정보 화면으로 개편한다.
9. 개인정보 변경 탭에 비밀번호 변경 입력란과 기존 회원탈퇴 기능을 구현한다.
10. 나의 구동이 탭에 현황, 현재 모습, 경험치 바와 보유 모습만 표시하는 모습 변경창을 구현한다.
11. 레벨별 이미지를 `public/characters/gudongi/`에 최적화해 연결한다.
12. 개인정보처리방침과 README 운영 문서를 갱신한다.
13. 자동 테스트와 데스크톱·모바일 수동 검수를 수행한다.
14. 사용자에게 화면 시안을 보여주고 승인을 받은 뒤에만 `npm run deploy`로 배포한다.

## 18. 보존 및 배포 원칙

- `wrangler.jsonc`의 Worker 이름, 계정 ID, `RANKINGS` 바인딩, `RankingStore` 클래스와 `global-book-ranking` 객체 키를 변경하지 않는다.
- 기존 추천, 즐겨찾기, 랭킹, 계정, 챌린지 테이블과 데이터를 삭제하거나 초기화하지 않는다.
- 스키마는 `CREATE TABLE IF NOT EXISTS`와 반복 실행 가능한 추가 방식으로 적용한다.
- 이미지 준비와 사용자 화면 승인 전에는 운영 배포하지 않는다.
- 운영 배포는 반드시 기존 안전 절차인 `npm run deploy`만 사용한다.
- 배포 전후 운영 랭킹, 즐겨찾기, 계정 수, 추천 세션과 챌린지 게시글 수를 비교한다.

## 19. 완료 조건

1. 로그인 계정별 구동이 모습, 이름, 레벨과 경험치가 서버에 안전하게 저장된다.
2. 5칸 경험치 바와 `EXP (현재/필요)`가 정확히 표시된다.
3. 하루 추천 도서는 최대 30권이고 추천 경험치는 최대 4 EXP다.
4. 성공 추천 1회당 1 EXP만 중복 없이 지급된다.
5. 챌린지 글쓰기의 기존 `이번 달성량` 입력값과 서버의 `challenge_posts.achievement`가 EXP의 유일한 원천으로 직접 연결된다.
6. 게시글 1개도 `이번 달성량 × 3`이 상한 없이 EXP로 반영되고, 게시글 수나 게시판 목표량으로 잘못 계산되지 않는다.
7. 챌린지 달성량 수정·삭제 후 경험치와 레벨이 정확히 재계산된다.
8. LV 1~5 기본 모습과 추가 모습이 표의 조건대로 누적 해금된다.
9. 로그인 후 `나의 정보`에 `개인정보 변경`과 `나의 구동이` 두 탭이 표시된다.
10. 개인정보 변경 탭에서 기존 비밀번호, 새 비밀번호, 새 비밀번호 확인을 입력해 안전하게 비밀번호를 변경할 수 있다.
11. 기존 회원탈퇴 기능이 개인정보 변경 탭 안에서 기존 절차대로 동작한다.
12. 나의 구동이 탭에서 현재 모습, 레벨, 경험치 현황과 보유 모습 수를 확인할 수 있다.
13. `모습 바꾸기`를 누르면 현재 보유 중인 모습만 표시되고 선택 결과가 계정에 저장된다.
14. 이미지가 없거나 실패해도 기능과 화면이 깨지지 않는다.
15. 기존 홈페이지 기능과 운영 데이터가 보존된다.
16. 자동 검사와 데스크톱·모바일 검수를 통과한다.
17. 사용자 승인 후에만 안전 배포하고 배포 전후 데이터 보존 결과를 보고한다.

## 20. 구현 전 정책 메모

이 문서는 다음 두 가지를 안전한 기본값으로 정했다.

1. 추천 EXP의 `+1`은 도서 1권당이 아니라 도서가 실제 제공된 추천 요청 1회당 지급한다.
2. 구동이 성장과 일일 30권 제한은 로그인 사용자 ID를 기준으로 한다. 비로그인 방문자는 경험치를 적립하지 않는다.

의도가 다르면 코드 작업 전에 이 두 규칙을 먼저 수정한다.
